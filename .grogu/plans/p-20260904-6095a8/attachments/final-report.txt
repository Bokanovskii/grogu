OBSERVATION, NOT A DEFECT

In a role-bearing launch the header's first row is crowded: the refusal sentence
"Approval is the user's. This workspace is reading as the engineer, so it can
read and comment only." runs at full width beside the Request changes button,
which squeezes the identity block so the plan id wraps to two lines and the
title truncates to "Sample plan for the fin...". Evidence
F05-engineer-sealed-panels.png at 1280x800.

The design stage says only that the refusal is shown "in place of the Approve
button, 13px/20px, --color-ink-2"; it sets no width, no wrapping rule and no
minimum for the identity block, so this is a gap in the specification rather
than a divergence from it, and it appears only in an agent-launched workspace -
never on the user's own review, where the refusal is not rendered
(F07-orphan-rail-order.png shows the reviewer header at the same width).
Recorded here so it is not lost; it is not routed as a defect.
