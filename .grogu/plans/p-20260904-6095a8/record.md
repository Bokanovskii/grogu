# Interactive plan review workspace

Plan `p-20260904-6095a8`. This is the account of how the plan changed while
it was being carried out; the stage files next to it are the plan.

## Defects found by the tester

- **d1** (resolved, routed to engineer): Blocking: no comment can be created from the browser. app.js commentOnSelection() and openDiagramComposer() build anchors with no body_digest and no revision; grogu_review.add_thread requires anchor['body_digest'] == digest(current_body), so every POST /api/threads returns 409 'the plan changed; reload it before adding this comment'. Text, node, edge and degraded-mode chip paths all fail; the composer shows 'Could not save. Your text is still here.' and no thread is ever stored. Fix: stamp body_digest and revision from the current stage_view onto every anchor before POST.
- **d2** (resolved, routed to engineer): Thread cards are not positioned to their marks: renderRail() appends them in creation order (measured mark tops 330/618 against card tops 236/314, constant 78px pitch). Violates the design clause 'Each thread card's top is positioned at its mark's vertical offset, and colliding cards are pushed down with at least 8px between them', which is the stated reason the rail was chosen over a drawer.
- **d3** (resolved, routed to engineer): grogu_markdown.py drops list continuation: a list item whose source text wraps onto the next indented line is emitted as a sibling paragraph, and the indented list after it becomes a new top-level list. Every stage body in this repository is written that way, including the design stage being reviewed.
- **d4** (resolved, routed to engineer): Four copy and chrome mismatches against the design stage, all small and all exact: (1) an empty 25px --color-surface strip under the header on every load, because #revision-banner has the hidden attribute but .revision-banner's CSS display overrides [hidden] - add .revision-banner[hidden] { display: none }; (2) an edge card header names Mermaid ids, 'edge . Anchor -> Review ("stored")', where the chip for the same edge correctly reads 'Anchor comments -> Review round' - both endpoints are the nodes' labels; (3) the drawer toggle reads 'Comments' where the spec says 'Comments - 3' with the open count, and the stage tab renders 'Implementation.5' where the spec says 'Implementation . 3' with a space either side; (4) the orphaned card reads 'orphaned since revision 1', the revision the anchor was created at, where the spec means the revision it orphaned at.
- **d5** (resolved, routed to engineer): Blocking: a written stage whose progress state is 'pending' renders 'Not written yet' with an empty rail. app.js renderStage() line 266 and renderRail() line 474 still branch on info.state === 'pending'; design revision 3 states that 'written' is the only field that decides whether a body exists and that progress state gates neither the document nor the rail. Measured: a testing stage with written=true and markdown=792 bytes shows the state block, 0 mapped spans and no threads. This is the ordinary review case - a stage the architect has just written or rewritten is exactly 'pending' - so the workspace is unusable for it, and it hides orphaned comments at the moment they matter most.
- **d6** (resolved, routed to engineer): The sealed and unwritten panels still hard-code a stage and a role. app.js line 262 always says 'The testing plan is written for the tester and is not readable by the engineer', so an engineer on the Evaluation tab is told about the testing plan; line 268 always says 'The architect writes the implementation plan before this stage can be reviewed', so the testing tab names implementation. Design revision 3 gives both strings parameterised as {stage} and {role} with worked examples.
- **d7** (resolved, routed to engineer): The round chip omits the 'changes requested' segment. app.js renderRoundChip() builds only 'round N', open and orphaned; design revision 3 fixes one chip format with segments in the order round, state, open, orphaned, so after a round is sent the chip must read 'round 1 . changes requested . 6 open'. Measured before and after request-changes: both 'round 1 . 6 open'.
- **d8** (resolved, routed to engineer): The disabled Request-changes button uses the wrong string while a round is with the architect. app.js line 202 sets title 'No open comments to send.' in the round.state === 'changes_requested' branch, which is untrue - six comments were open. Design revision 3 gives two strings for two reasons: 'No open comments to send.' when nothing is open, and 'Round N is with the architect. Add a comment to open round N+1.' while a round is out. The second string is already rendered correctly in the round line, so only the button's title and aria-describedby are wrong.
- **d9** (resolved, routed to engineer): Minor: rail card DOM order is creation order, not document order. With one orphaned thread pinned at the top the DOM order is c7,c1,c2,c3,c4,c5,c6 while the visual order is c7,c1,c4,c5,c6,c2,c3, so keyboard and screen-reader order through the rail does not match what is on screen. Positioning itself is correct: every card with a visible mark sits at that mark's offset within 2px when no orphan section is pinned, and every visual gap is at least 8px. Design revision 3 asks for cards 'in document order' both visually and in the tab order.
- **d10** (resolved, routed to engineer): In grogu_review_server.py _token_exchange(), the single-use launch token is not invalidated after exchange. A second request reusing the already-spent token (GET /?t=<token>) returns 303 See Other and issues another session cookie instead of failing closed with 403 Forbidden. Violates sealed testing plan check 41 and the single-use launch token security invariant.
